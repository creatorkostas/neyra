# Agent instructions

Before changing code, follow the architecture guide link in the README and read
the guide to understand module ownership and runtime boundaries.

## Pull request descriptions

When preparing a pull request, fill in `.github/pull_request_template.md` using
these limits and instructions:

- **Problem:** Write one simple paragraph in 2–3 lines. Explain what is wrong
  or needed and its impact. Keep the fix out of this section.
- **Change and fix:** Use no more than 20 lines. Describe the relevant changes
  and explain how they address the problem.
- **Verification:** Use no more than 20 lines. List the relevant automated
  checks or manual steps and their results. If verification was not done, say
  so clearly and explain what remains unverified.
- **Implementation attribution:** Name the human PR creator and any AI model or
  tool that helped implement the solution. Write “None” when no AI or tool
  assistance was used.

Keep the description focused on this PR, report checks truthfully, and leave out
unrelated implementation details.
